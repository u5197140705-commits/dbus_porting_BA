## 3. Errors Encountered and Resolutions

*   **`make.bat` execution failure on Linux:**
    *   **Error:** `bash: ./make.bat: Permission denied`, followed by "command not found" for Windows batch commands.
    *   **Resolution:** Identified `make.bat` as a Windows batch script. Attempted `chmod +x` but it didn't resolve the underlying issue of Windows commands. The user provided a `west build` command for Zephyr, which was the correct approach for the Linux environment.
*   **"Unknown derivative STM32G071CB" during `make`:**
    *   **Error:** The `common/prog/MSP/stm32g0/derivative.mak` file failed to parse the derivative name, likely due to shell differences between Windows and Linux.
    *   **Resolution:** This issue was bypassed by switching to the Zephyr `west build` system, which handles device tree and Kconfig for board-specific configurations.
*   **"implicit declaration of function 'spi_transceive_cb'" and "undefined reference to `K_MSEC_TO_MS`" during `west build`:**
    *   **Error:** The `spi_transceive_cb` function was used without a proper declaration, and `K_MSEC_TO_MS` was not resolved by the linker.
    *   **Resolution:**
        1.  Removed an incorrect forward declaration of `spi_transceive_cb` from `zephyr_dbus_driver/tests/inc/spi_abstraction.h`.
        2.  Added `CONFIG_SPI_ASYNC=y` to `zephyr_dbus_driver/prj.conf` to enable asynchronous SPI operations, which makes `spi_transceive_cb` available.
        3.  Corrected the value of `CONFIG_SYS_CLOCK_TICKS_PER_SEC` in `zephyr_dbus_driver/prj.conf` to be a pure integer.
        4.  Added a fallback `#ifndef K_MSEC_TO_MS` definition in `zephyr_dbus_driver/src/spi_abstraction.c` to ensure the macro is available.
        5.  Included `<zephyr/sys/util.h>` and `<zephyr/timing/timing.h>` in `spi_abstraction.c` to ensure all necessary time-related macros are available.
